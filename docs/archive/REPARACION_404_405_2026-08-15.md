# Corrección Happy Paws — 404 / 405 / Dashboard

## Problemas encontrados

1. Existía `views/dashboard/index.html`, pero no existía ningún controlador para `/dashboard`.
2. El `WebAuthenticationSuccessHandler` redirigía a `/dashboard/cliente` y `/dashboard/colaboradores`, pero esas rutas tampoco tenían controlador.
3. `/dashboard/exportar` estaba declarado en SecurityConfig, pero no tenía endpoint.
4. El enlace `/admin` existía en el dashboard, pero el único controlador administrativo era `/admin/settings`.
5. Había un formulario heredado de clientes que hacía POST a `/clientes`, mientras el flujo principal guardaba en `/clientes/guardar`. Se agregó compatibilidad para evitar HTTP 405.
6. La regla `/dashboard/**` aparecía antes que `/dashboard/cliente/**`, lo que podía hacer que un usuario CLIENTE recibiera 403 aunque tuviera `DASHBOARD_CLIENTE_VER`. Se reordenaron las reglas.

## Cambios

- Nuevo `DashboardController` con:
  - `GET /dashboard`
  - `GET /dashboard/colaboradores`
  - `GET /dashboard/cliente`
  - `GET /dashboard/exportar`
- Nuevo `AdminAliasController` con `GET /admin` -> `/admin/settings`.
- SecurityConfig corregido para evaluar primero el dashboard del cliente.
- Endpoint de exportación CSV implementado.
- Compatibilidad `POST /clientes` agregada.
- Formulario heredado de clientes actualizado a `/clientes/guardar`.
- Fragmentos de la vista 403 actualizados a sintaxis Thymeleaf moderna.

## Base de datos / RBAC

El `DataInitializer` incluido ya reasigna siempre `Permission.module` antes de guardar cada permiso y usa `saveAndFlush`, corrigiendo el caso de `module_id = NULL` de registros existentes.

## Verificación

El entorno de ejecución usado para revisar el ZIP no tenía Maven descargado y no pudo descargar Maven Wrapper por falta de acceso al repositorio Maven. Por tanto, la compilación completa debe validarse en local o en Render con el siguiente comando:

```bash
./mvnw -DskipTests clean package
```

El proyecto ya incluye `mvnw`.
